# Meals at Work / 工作餐

RimWorld 1.6 模组，需要 Harmony。版本：0.5.4（饥饿订单机制已完成实机回归）。原名 Desk Lunch。

殖民者在工作台制作或研究时，如果饥饿程度已达到原版找饭阈值，且背包里有符合饮食政策的成品餐食，就会边工作边吃饭。制作期间需要外出取餐时，自动进入 Lunch Break，吃完回到原任务。没有手动按钮。

0.4.3 增加可选兼容：Pick Up And Haul 的搬运货物和 Common Sense 的待卸货食物不作为随身工作餐，也不阻止下单；配送餐食单独成堆，避免合并进货物。Common Sense 开启高级进餐清洁时也能选择空工作台，沿用它的清洁与行走流程。Schedule Everything 的烹饪、锻造、裁缝、艺术、制作、研究排班允许工作餐，其他专用排班仍不允许。这些模组均非必需依赖。真实游戏与存读档记录见 `Docs/validation/2026-09-06-compatibility.md`。

0.4.2 修复原版进餐结束后一 tick 站立过渡误取消午休恢复的问题；配送现在检查食物社会归属。工作餐和借用空台统一获得“在工作台上吃饭：我应该在真正的餐桌上吃饭”（−1／1小时），同时继承原版“在地上吃饭”的思想禁用规则：苦行者、相关信条/基因等不应受到此惩罚，已有记忆也随规则失效。非餐厅不获得餐厅印象加成。

已通过 GABS 运行真实游戏，覆盖送餐、配送竞争、一小时超时、时间表切换、工作完成驻留和午休往返存读档，并在 Common Sense + Pick Up And Haul 组合的新测试地图上复测基本流程。完整记录与剩余兼容风险见源码目录 `Docs/validation/2026-09-06-review.md`。这不代表所有模组设置与存档组合均已验证。

0.5.4 支持有普通 Food 需求和库存的玩家机械体：可收餐并在原版制作过程中边工作边吃。无食物需求的原版机械体不受影响，HardworkingKz 动物暂不接入；独立进食驱动仍需专用适配。实机记录见 `Docs/validation/2026-09-07-food-mechs.md`。

完整工作者与工作流程兼容性审查见 `Docs/validation/2026-09-06-worker-compatibility.md`。HardworkingKz 动物与 Hospitality 访客目前未完整适配，不能按人类殖民者支持范围推定兼容。

## 自动送餐（0.5.0）

不再预测饭点或提前下单。饥饿指达到原版找饭阈值。已有随身餐时也可先接制作任务，但不会重复下单；仍尊重“优先外出吃饭”设置。

- 原本准备自动找饭时，再按角色实际工作优先级查询下一项工作。如果返回工作台制作任务，就直接采用该任务并创建订单；没有工作或下一项工作不是工作台制作时，保持原来的找饭任务。不会跳过更高优先级的其他工作来强选制作，也不替换玩家明确排队的吃饭命令。
- 在整个制作任务中检查饥饿，包含去工作台、寻找和搬运原料、加工、搬出产品等阶段；饿了且没有可用随身餐时创建订单。尚未饥饿不会创建订单。范围为目标 A 是制作工作台的 `JobDriver_DoBill` 及其子类；研究仍支持随身工作餐，但不创建配送订单。
- 订单绑定收餐者，每人最多一单。离台、短工作切换、换台、普通改派、删除工作台账单或切换时间表不会直接取消订单。配送员追踪收餐者本人，将一份饭转入其背包，且不与搬运货物堆栈合并。
- **默认有效期 2 个游戏小时，从下单时起计时。** 尚无人接单、正在取餐和已经携餐均使用同一个期限。接单、重新接单、换工作和存读档不重置时钟。设置中可调整为 0～2 小时；0 表示不创建配送订单，也不延后找饭。
- 工作／自由活动及受支持的自定义工作排班中，有效订单会暂缓普通找饭；不要求配送员已经拿到餐。娱乐／睡眠／冥想时不延后找饭，但保留仍可交付的订单。饥饿降至原版找饭阈值的 40% 以下时也恢复主动找饭，避免为了订单持续挨饿；订单仍可交付。
- 配送员中断时放下实际携带的餐食并释放接单权，订单可由其他配送员接手，期限不变。不存在配送员时等待至订单超时，随后恢复正常找饭。
- **结束条件：** 交餐成功、已不再饥饿、已有合适的随身餐、订单超时、收餐者无法接收（征召、倒地、死亡、精神失常、离图、失去受控殖民者身份或库存等），或关闭配送。不能接收的检查沿用本模组的收餐资格，不因普通离台失败。地图清理最多延迟 60 ticks，找饭查询和交餐即时检查。
- 超时后同一次饥饿期间不重新下单；解除饥饿后才能在下一次饥饿时重新下单。超时限制随存档保存。

送餐仍属于搬运工作，优先级略高于普通搬运，只配送已有的新鲜成品餐食，尊重饮食政策及食物社会归属，不烹饪或操作营养膏机。开始等待不会锁住工作台或要求收餐者原地驻留。食物送达后沿用随身工作餐或普通吃饭机制。

订单使用原来的存档字段；旧订单改按其原始创建时刻计算新的有效期，较早创建的旧订单可能在升级后立即超时。旧的提前量、离台宽限设置不再参与行为，也不再显示。

## 时间表与用餐预留

订单存续和工作台预留分别判断。娱乐／睡眠／冥想时，既有配送订单仍可交付，但不创建新订单、不延后找饭、不启动新的工作餐，并取消外出 Lunch Break 的强制返回计划。正在吃的普通饭可以继续；正在吃工作餐的角色可继续吃，原版安排其他任务时仍正常中断。

Schedule Everything 的烹饪、锻造、裁缝、艺术、制作、研究排班，以及显式声明 `DeskLunch.WorkMealScheduleExtension.allowWorkMeals=true` 的排班，允许开始工作餐及适用范围内的订单。未知排班不创建订单、不暂缓找饭，但也不单独取消既有订单。

实机验收记录：`Docs/validation/2026-09-06-hunger-orders.md`。

## 统一的用餐预留

两种模式共用 `WorkMealSession` / `WorkMealReservations`：记录原工作任务、工作台、半成品或已摆放的材料、取消条件与最长保护时间。底层沿用原版任务预留，不另外修改物品的“禁止”标记。

| 模式 | 工作进度 | 吃完以后 |
| --- | --- | --- |
| 在工作台吃随身餐食 | 80% 速度 | 继续当前制作；工作先完成则原地吃完再结算 |
| 自动 Lunch Break | 暂停 | 返回原工作台，恢复剩余工作量和技能经验计时 |

Lunch Break 默认启用：保留原有随身用餐优先行为；也可在设置中勾选“优先外出吃饭”。食物按原版选择；用餐位置在原版基础上增加空工作台。正常饮食政策与进食速度继续生效。在正式餐桌用餐不会产生本模组的 −1 减益；借用工作台时会产生，没有合适用餐表面时仍可能触发原版无桌惩罚。

外出时，专用可暂停任务留在原版队列中，继续持有工作台、交互位置和材料的预留；自动搬运会检查共同的用餐记录。返回后跳过重新收集材料/创建半成品，恢复准确进度。适用于原版制作工作流，包含没有实体半成品、仅有已摆放材料的配方。

**自动取消：** 被改派到另一任务、征召、倒地/死亡、精神失常、离开地图、工作台失效、账单删除或暂停、工作类型禁用、保护物品失效，或者超过 **3 个游戏小时**（含往返路程）。任务切换和离图即时处理，其他异常每 60 ticks 检查一次。取消只删除本次暂停任务、解除相关保护；不会销毁半成品，也不会清空玩家的其他命令。取消外出午休的返回计划后，已在执行的普通吃饭过程可以继续。

正常自动找工作的其他角色会跳过预留中的工作台。玩家强制抢占或强制搬运沿用原版优先权，并撤销用餐保护。桌边用餐结束/取消时，仍在工作的原任务继续持有它需要的正常预留，直到工作结束。

首版 Lunch Break 自动恢复支持原版 `JobDriver_DoBill` 制作流程；研究仍支持桌边吃饭，但外出研究午休不保存专用返回计划。自定义制作驱动、需要先收割/给营养膏机填料等前置任务的取食流程尚未接入，按原版中断处理。

## 空工作台兼作餐桌

默认开启，全自动。殖民者携带食物寻找用餐位置时，会考虑自己阵营、可到达、安全且未被预留的 `Building_WorkTable`，在其交互格用餐（有座位则使用座位）。

- **准入条件是账单列表完全为空。** 暂停的、次数已完成的或缺材料的账单都仍算有账单。不是要求工作台本身不支持任何配方。
- 沿用食物的找椅范围。按距离成本选择：正式餐桌为实际直线距离，空工作台默认按两倍距离计算；成本相同时选正式餐桌。倍率可设为 1～5，沿用餐食搜索范围及可达性检查。
- 选中时用当前吃饭任务预留工作台与用餐位置。此后不再检查账单数量，因此途中或吃到一半新增账单都不会赶人；自动制作任务等预留释放后才能使用工作台。
- 复用 `WorkMealSession`，普通用餐者可只持有用餐位置；Lunch Break 用餐者可同时保留原制作台和另一张借用台。
- 使用原餐食图像在台面上显示餐盘，不改变工作台全局的表面类型。
- 吃完获得同一个 **−1、持续 1 小时、不叠加、可关闭**的“在工作台用餐”记忆。本次不叠加原版无桌用餐或餐厅环境记忆，食物本身的效果保留。
- 吃完、改派、征召、失能、离图等情况自动清理；仍沿用 3 小时的最长保护期。新增账单本身不属于取消条件。玩家强制抢占继续沿用原版规则。

- 进餐期间工作进度、相关技能经验及该工作阶段的舒适度累积按 80% 速度结算；走路、搬材料和其他工作不受影响。
- 进餐耗时沿用餐食的基础进食时间及角色的进食速度。完成时消耗真实餐食并获得营养，保留原版食物品质、食材、食物中毒及进食后果。
- 吃完获得 −1 心情减益，持续 **1 个游戏小时**，不叠加。设置中可关闭；关闭也会取消已有工作餐记忆的影响。
- 这次工作餐不额外产生“在地上吃饭”或餐厅环境记忆；此前已有的记忆不会被删除。
- 正在吃饭时，工作报告显示进餐百分比。
- 进餐时使用餐食本身的贴图，在靠近角色的工作台占地格上绘制单份餐盘（原版堆叠餐食使用单份图）。真实食物留在背包中，桌面上的餐盘不是可以搬运或使用的物品。支持普通渲染和远景缓存路径，不在肖像或隐形状态中显示。特殊模组工作台的遮挡和贴图偏移仍需实机确认。
- 如果工作先完成，角色会留在原工作位置吃完余下的饭，再进入产物生成/入库等后续流程。驻留时不继续生产、不增加工作经验；制作任务的产物会在饭吃完后结算。研究阶段到期、当前研究项目完成或被取消时也可吃完已有的饭。
- 驻留保留原任务对工作台、交互位置/座位的预留，其他角色自动寻找工作时会跳过该工作台。不会新建额外的永久锁。吃完后沿用原任务的正常释放时机；征召等强制中断按原版释放。玩家强制让另一角色使用该工作台时，原版可能抢占预留并中断当前角色。
- 没有餐食、食物腐坏或不再符合饮食政策时恢复正常找饭。征召、倒地、精神失常、任务失败或进入饥饿状态（营养耗尽）会取消工作餐。工作台被毁、失火、账单被删除等原版失败条件仍生效。
- 中断前不消耗餐食、不提前加营养；已完成的工作进度保留。下次进餐重新计时。
- 保存进行中的进餐计时和餐食引用，读档后继续。

## 安装

将 `MealsAtWork` 文件夹复制到游戏的 `Mods` 目录，启用 Harmony 和 Meals at Work，然后重启游戏。此项目不会自动修改现有模组列表或存档。

从 Desk Lunch 升级时，用新文件夹替换旧文件夹，不要同时保留两个版本。包标识 `ch4acko3.desklunch`、序列化类型、心情定义和存档字段保留，便于已有存档识别。原 `DeskLunch` 文件夹对应的设置会在新位置没有设置时自动读取。程序集改为 `MealsAtWork.dll`。

桌边用餐只从**自己的背包**取餐，并排除已识别的待搬运/卸货餐食。Lunch Break 可以按原版流程去货架取食或使用有料的营养膏机；自动配送只搬运已有的成品餐食。

支持使用原版 `Toils_Recipe.DoRecipeWork` 的工作台制作，以及原版研究。自定义工作驱动、其他模组改写的吃饭/工作流程和多人模式尚未验证。优先放在修改工作流程的模组之后测试。

## 后续送餐接口

配送模组只需将餐食放入目标 pawn 的 `inventory.innerContainer`，下一次工作更新即可发现，不需要新建进餐任务。`LunchUtility.EnableFor(Toil)` 可为其他工作台模组的静止工作阶段接入相同逻辑；仅接受带 `tickIntervalAction` 的 toil，工作目标 A 必须是工作台或研究台。

## 构建与检查

```powershell
dotnet build Source/MealsAtWork/MealsAtWork.csproj -c Release
dotnet build Tests/MealsAtWork.Tests.csproj -c Release
& ./Tests/bin/Release/net48/MealsAtWork.Tests.exe
```

默认引用本机 `D:\App\Steam` 下的游戏与 Harmony；可通过 MSBuild 属性 `RimWorldManagedDir`、`HarmonyAssemblyPath` 覆盖。构建输出自动复制到 `Assemblies`。

自动检查覆盖工作时间折算、XML与翻译、已安装游戏程序集上的 Harmony 补丁安装、对象池复用、工作完成驻留、两种模式相同的保护对象、进度恢复、取消的幂等性和其他队列命令保留，以及空台准入、新账单不打断已有用餐、暂停账单不算空台。涉及地图/食物的检查使用隔离替身；不等同于实机绘制、读档或多角色竞争验证。

## 实机验收清单

1. 原版 + Harmony + Meals at Work，殖民者背包放两份简单饭，安排长制作任务；将饥饿调到找饭阈值以下。确认留在工作台、进餐期间继续工作、吃完扣一份饭并恢复营养。
2. 研究台重复测试；无餐食对照组应正常离开找饭，搬材料阶段不应触发工作餐。
3. 固定技能和环境，对照相同游戏时长的制作/研究进度；进餐时约为 80%，吃完恢复正常。
4. 吃到一半存档读档，确认继续计时，只消耗一次；吃到一半征召，确认餐食保留、下次重新计时。
5. 进餐中移除餐食、更改饮食政策、关闭功能，确认不凭空补充营养，恢复普通行为。
6. 确认 −1 记忆在吃完后出现，约 2500 ticks 后消失，不产生新的无桌用餐记忆；关闭减益后立即归零。
7. 食用精致/奢华餐、含禁忌食材的允许餐食，以及有食物中毒风险的饭，确认对应原版效果仍生效。
8. 工作短于进餐时间时确认原地吃完，驻留时工作进度、技能经验不再增长，吃完后只生成一次产物；驻留中保存/读档后继续。
9. 给第二个角色安排相同工作台：自动找工作应跳过，第一人离开后恢复可用；强制右键命令应沿用原版抢占行为，不能导致两人重叠作业或永久锁台。
10. 检查四种朝向、小/大工作台、研究台、远近缩放和肖像；桌面显示单份餐食，饭吃完或被打断后消失。检查多人同时进餐、三倍速、已有存档加入模组等情况。
11. 制作进行一半、没有随身饭时触发饥饿：自动外出取餐，其他搬运者不移动半成品；吃完返回，剩余工作量准确、无重复材料和产品。无实体半成品的配方也要测试。
12. 外出和返回途中分别存档读档；队列中的工作任务、保护对象和截止时间应保留，返回后只恢复一次。
13. 午休中改派、征召、倒地、离图、删账单、停工台、禁用工作类型；确认保护撤销且无幽灵预留。保留队列中与午休无关的其他命令。
14. 拉长路线超过 3 小时，确认自动取消返回、释放台子但不销毁半成品。切换“优先外出吃饭”和禁用 Lunch Break，检查自动流程和清理。
15. 空工作台放在饭菜附近、正式餐桌更远：餐桌距离不超过空台距离的两倍时选餐桌；更远时就近借用空台（默认权重）。测试有椅/无椅、四个朝向，餐盘显示在台面。
16. 吃到一半新增制作账单，另一个可工作的殖民者不能抢占；饭吃完后可正常接单。已有暂停账单的台子不能被新用餐者选中。
17. 普通用餐与 Lunch Break 借用另一张空台分别存档读档，确认新增账单不会失去用餐预留；打断时不留下预留。
18. 确认借用台只产生 −1/1 小时减益，没有新增的“在地上吃饭”；关闭心情减益后不产生该效果。
19. 饥饿时下一项工作为制作：先接制作；前往工作台和备料时下单。不饿、无工作或下一工作不是制作时不下单、不替换吃饭任务。
20. 下单后离台、换工作、切娱乐时间，订单应保留；娱乐和紧急饥饿不压制普通找饭。
21. 配送员取餐前后中断，订单可重新接单且不刷新期限；两小时后恢复找饭，同次饥饿不循环下单。
22. 等待、移动收餐、配送中断、超时冷却分别存读档；检查只交付一份、没有永久等待或额外工作台预留。
