# Meals at Work 0.4.2 审查与实机记录

用户指定两个 `gpt-5.6-sol / medium` subagent，分别执行生命周期审查与工坊兼容性调查。主代理通过本机 GABS 启动 RimWorld 1.6，在新建 quick-test 地图上运行测试专用 `MealsLive` 模组。此探针仅布置场景、调用生产入口并记录真实游戏 tick，不随发布包分发。

## 修复与最新规则

- **已复现并修复：午休恢复被原版一 tick 过渡误取消。** 原版 `EndCurrentJob(Succeeded)` 先插入 `Wait_MaintainPosture(1)`，原实现把它当成改派，清掉 ResumeWork 队列。修复只登记这一过渡任务的 ID；任意其他等待/任务仍不能冒充。修复前实机重新生成 DoBill#284/291，修复后恢复原来的 ResumeWork#36，回台 workLeft 由保存的 1536.4026 继续下降。过渡 ID 随存档保存。
- **已复现并修复：配送绕过食物社会归属。** 实际封闭囚室中的餐食通过旧 MealFor 过滤，新 Deliverable 过滤拒绝。取餐前再次检查归属、禁用状态与收餐者政策。
- **按用户要求统一思想：** “在工作台上吃饭：我应该在真正的餐桌上吃饭”，−1，2500 ticks，涵盖工作餐与借用空台。通过 `ThoughtUtility.CanGetThought(AteWithoutTable, checkIfNullified:true)` 继承原版特性/信条/基因等禁用判断，并同步使已有记忆失效。实际 pawn 普通状态得 −1；获得 Ascetic 后已有记忆为 0 并可丢弃，新餐无该记忆。
- 工坊等非餐厅不获得餐厅印象加成。借用空台仅在房间角色实际为 `DiningRoom` 时保留相应原版思想。房间印象不是单独的美观数值。

## 已执行

最小环境：Harmony + Core + Biotech + Meals at Work + RimBridgeServer + 测试探针。

| 场景 | 证据与结果 |
|---|---|
| 原生制作触发订单、取一份饭、直接交接库存 | DoBill#36 产生订单，DeliverMeal#79 持有一份真实饭，交接后进入原工作 toil 咀嚼 |
| pending / 已取餐途中存读档 | 订单与原 delivery job ID 保留，成功到达；没有第二份配送 |
| 等餐一小时 | waitStarted=562；tick3060 仍在等，组件在 tick3120 前清单，配送结束后实物总数仍为10；60 tick清理粒度，不是无限等待 |
| 配送竞争 | 两个原生候选 job，第一人启动并预留后，第二人的 TryMakePreToilReservations 返回 false |
| 睡眠时段取消等待 | 同一 tick 的 ShouldWait 从 true 变 false；配送后续退出、餐保留 |
| 工作餐速度 | 同一 pawn 无餐每30 ticks 减12工作量；咀嚼时减9.6，比例80% |
| 工作已完成但未吃完时存读档 | workLeft=-0.6 保持不再推进；餐后 meals=9、pants=1、billLeft=19、station reservations=0，只结算一次 |
| 外出午休中与返回路上存读档 | 修复后仍为原 ResumeWork#36，回台恢复进度，保留一个台预留 |
| 午休途中切睡眠 | 当前吃饭可继续，session/queue 清空，station reservations=0，无强制返回 |
| 画面 | 实际截屏见 workstation-meal.png：餐盘位于裁缝台桌面；未全面测试四朝向、所有模组工作台与缩放 |
| 心情与食物归属 | events.txt 中 thoughtChecks 与 socialChecks 为 PASS；这是游戏内生产方法测试，非完整用餐动画测试 |

另外一起启用 **Common Sense + Pick Up And Haul + HugsLib**，在新测试地图上重做原生订单/送餐/工作餐和午休恢复，成功；记录中为工作 toil21、ResumeWork#51。上述两个组合流程未出现新 error 日志。不能据此宣称两个模组的全部设置/库存场景完全兼容。

**额外复现的组合限制：** 给“正在制作中”的原版测试存档临时加入 Common Sense 后再加载，原来的 toilIndex14 在新序列中对应不同操作，出现“Worker tried to place hauled thing in cell but is not hauling anything”。重新建图、从一开始启用组合后未复现。不要把中途替换工作驱动的存档当成稳定兼容配置；切换此类模组前应先结束活动工作。测试过程没有覆盖任何用户正式存档。

## 工坊调查

- [Schedule Everything!](https://steamcommunity.com/sharedfiles/filedetails/?id=3486341728)：自定义工作时间分配会被当前 Work/Anything 白名单排除，确认是功能限制。未安装实测，也尚未添加专用适配。
- [Pick Up And Haul](https://steamcommunity.com/sharedfiles/filedetails/?id=1279012058)：基本流程组合已跑通。待专项测试：带有 hauled 标记的饭在中断搬运后进入制作，是否被当成随身午餐；当前 FindMeal 未识别其货物标记。[作者源码](https://github.com/Mehni/PickUpAndHaul)
- [Common Sense](https://steamcommunity.com/sharedfiles/filedetails/?id=1561769193)：基本流程组合已跑通。待专项测试：高级清洁进餐选座与空台选座是否短时双占座，以及用成品饭作原料时库存货物是否误食。仍调用原版 DoRecipeWork，所以不能仅因双方补丁重叠宣称全面冲突。[作者源码](https://github.com/catgirlfighter/RimWorld_CommonSense)
- [RimThreaded](https://steamcommunity.com/sharedfiles/filedetails/?id=2222907981)：调查到的正式版本止于1.4，不作为本1.6模组已验证组合；没有线程安全保证。
- Work Tab、Better Pawn Control、Performance Optimizer 等未发现同等级直接冲突；这只是源码/机制筛查，未全部实测。
