# 0.6.0 配送人手与批量配送

下单和饥饿工作选择共用配送人手检查，工作资格包括真实 WorkGiver 列表、工作开关、原版工作限制、操作与移动能力、地图、区域和可达性。机械体检查受控状态与工作模式；训练完成的动物通过自身 JobGiver_Haul 分支领取配送。JobDriver_Research 及子类可创建研究配送订单。

一趟最多六单，每单一份，按各自饮食规则选择餐食并预留总数量。餐食先集中取入配送库存，随后就近逐单交付。通用搬运容量限制所有配送者，具备商队负重能力的个体同时按重量限制。餐食分别记录为配送货物，和其他模组的搬运货物判定共同工作。

单个收餐者失效、餐食丢失、不可达或订单超时会释放对应站点，继续剩余路线。配送者中断会释放整批接单权，放回实际餐食，保留订单原始时刻。配送人手消失时保留可交付订单，恢复主动找饭。

## 验证

通过 GABS 在真实 RimWorld 1.6 中运行独立 MealsLiveProbe；加载的兼容模组包括 WorkTab、Common Sense。测试存档均为专用 MealsBatch_* 文件。

- 关闭唯一配送者的搬运工作：不创建订单，不因为等待送餐而优先接工作；收餐者本人不计为自己的配送者。
- 启用搬运工作：允许下单；征召配送者：资格失效。
- 未训练哈士奇：不可配送；完成搬运训练：可配送。
- 受控 Lifter 工作模式：可配送；充电模式：不可配送。
- 已下单后配送者被征召：订单期限保留，主动找饭恢复。
- 人类配送者一次领取三单，一位收餐者只允许生存包装餐：正确分配三份餐食，并在交餐前取齐。
- 人类取齐餐食后保存重载：餐食引用、货物标记和三单归属保持。征召其中一位收餐者后，其余两单完成。
- 哈士奇经实际 JobGiver_Haul 入口领取三单，取齐不同种类餐食后保存重载，继续逐单交付。
- 人类配送者携带三份餐时被征召：所有货物放回地图、所有接单权释放、订单创建时间保持；解除征召后原版工作调度重新领取三单并完成。
- 本机完整回归：1,177,644 项断言，21 个 Harmony 目标。研究任务及工作台类型匹配另有回归断言。

测试中修正了以商队容量判断普通搬运动物的错误：非驮运动物的商队容量为零，但具有正常搬运容量。实机调试亦发现测试存档存在重复 Worker/Courier 名称，探针改为选取新建角色。初始旧测试存档自带的搬运物体丢失日志、随机生成角色的禁用工作日志均记录在测试阶段；配送流程自身通过上述测试。

研究配送的本轮验证涵盖任务识别回归；第三方完全自定义调度器需按其实际工作入口进行实机验证。
